How the edition is made

Pipeline

Every morning at 09:00 UTC a GitHub Actions run collects the headlines, keeps template pages out, stores everything on a data branch, scores it with two models and rebuilds this site. This page reads the status report that run leaves behind.

Read from status.json.

Architecture

Boxes on paper are steps; shaded boxes are files kept on the data branch. No server runs in production: the site is static files.

  1. Check out main, plus the data branch into data/.
  2. Backfill past days, only when the workflow is started by hand with backfill_days above 0.
  3. Run: one RSS request per topic, quality filter, raw JSONL, load into DuckDB, score what is missing, export Parquet and JSON.
  4. Compare VADER and FinBERT over the whole history.
  5. Commit the raw JSONL and Parquet files to the data branch.
  6. Deploy the frontend and the JSON exports to GitHub Pages.
